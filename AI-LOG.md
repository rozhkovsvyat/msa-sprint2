# AI-log

Работа выполнена Святославом Рожковым с ИИ-ассистентами Claude Opus 5.5 и Codex GPT‑6.1 Sol; по правилам курса их вклад раскрыт ниже.

## Решения автора

| Вопрос | Решение | Как пришли к нему |
| :- | :- | :- |
| Первый выносимый модуль | Бронирование | ИИ предложил варианты и критерии; автор выбрал бронирование: в монолите от него никто не зависит, и в нём уже есть шов — готовый прокси |
| Язык новых сервисов | C#/.NET | ИИ рекомендовал Java ради однородности с командой Hotelio. Автор возразил: задание разрешает любой язык, а в заготовках курса уже есть Node.js и Go. Компромисс записан в ADR |
| Миграция данных | Остановка записи в монолите, ops-джоба переноса, откат обратной джобой | Автор опирался на свой опыт переноса данных ops-джобами и отказался от постоянной обратной синхронизации: при одном писателе она не нужна |
| Пустые даты бронирований | Подставлять время миграции с пометкой | Выбор автора после того, как ИИ нашёл, что монолит не заполняет дату, а прокси не принимает пустую |
| Надёжная публикация событий | Transactional outbox | Предложение ИИ, принято автором |
| Название отеля в кабинете | `null` и реальные поля вместо выдуманного значения | Автор попросил перепроверить, действительно ли у монолита нет названий; после проверки по jar, коду, БД и API выбрал этот вариант |
| `@override` поля скидки | По схеме задания: `discountPercent` с `@requires(fields: "promoCode")` — скидка промокода по справочнику | ИИ предлагал оставить в поле скидку, сохранённую при бронировании. Автор выбрал вариант задания: применённая скидка остаётся в цене бронирования в booking-service |
| Fallback в Istio | Выбрать после проверки на стенде | Решение автора; на стенде выбран `failoverPriority` |

## Что сделал ИИ

- Разобрал теорию спринта, исходный репозиторий и стенд, нашёл расхождения задания с кодом: прокси переносит и список бронирований, ID — число, дата не проверяется на пустоту, `ddl-auto: create` стирает данные при перезапуске, базовые образы устарели, прокси падает на списке без `userId`.
- Подготовил черновики ADR, схем C4 и отчётов; архитектурные решения обсуждались с автором (таблица выше).
- Написал код сервисов, подграфов, ops-джобы, Helm-чартов, пайплайна, манифестов Istio и проверочных скриптов.
- Выполнил прогоны на стенде (macOS, Colima, Minikube, Istio) и отрицательные контроли.

## Как проверялось

Модульные и контрактные тесты (`dotnet test`, `npm test`), регресс курса на стенде задания 2, проверка доставки событий при остановке Kafka, учения по переключению и откату, пайплайн в gitlab-ci-local и проверочные скрипты Istio. Результаты приложены в `tasks/*/results`. Нагрузочного испытания и развёртывания во внешний кластер с registry в работе нет.

Работа дополнительно проверялась ИИ-ревью; найденные замечания исправлены.
